## 4. 部署情况（backup writer 测试形态）

**生产形态**：k8s NodeCluster（production-graviton，ns `blockchain-tempo`），node group `hybrid`(主)+`hybrid-seed`(seed)；容器 = `tempo` node + `jrpcx` sidecar；follow 模式（无 validator key、无独立 CL）。

**关于"通用节点"**：tempo **尚未迁移通用节点管线**（node `trace_debankBlock` → background-tracer sidecar → S3/Kafka → leafage-evm/DeBankCore，dev 验证完但生产 background-tracer 仍是上线阻塞项，见 `docs/generic-node.md`）。生产当前是 **node 直接服务自定义 RPC**（`eth_multiCall`/`pre_traceMany`/`trace_debankBlock`，pull 拉取）。

**测试部署**：单 `tempo node` 容器，dev box，从生产 seed 快照（约 5 天龄）建卷恢复，`--follow=auto` 跟随官方 WS 同步。
- **is_backup：无需注入**——node 是被动 RPC server，不向 Kafka/S3/etcd 投递、不选主；只跑 node 容器、端口绑 127.0.0.1、不挂进生产 RPC 端点组 = 天然隔离。
- **p2p 清理**（reth 系）：首启前 `rm -rf <datadir>/discovery-secret <datadir>/known-peers.json`（照生产 bootnode initContainer），让其重生，避免与生产 writer p2p 身份相撞。
