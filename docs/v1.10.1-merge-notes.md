## 1. 升级背景与必要性

**结论先行：必升（强制硬分叉，有硬截止期）。无可不升的选项。** 官方 release 头部 IMPORTANT 明示 "This release is required for the T7 network upgrade … Node operators must update before activation or their nodes will fall out of sync"，Update Priority 表 Validators / RPC Nodes 均 **High**，明示 "Nodes that are not updated will fall out of sync at the T7 activation timestamp"。这正中 DeBank 部署角色（只读 RPC/follow 副本），是必要性高的最强信号——与 oas v1.9.1 的 optional/not-mandatory 先例相反。

- **v1.10.1 = T7 网络升级**：testnet 2026-07-02 16:00 CEST（ts `1783000800`）、**mainnet 2026-07-09 16:00 CEST（ts `1783605600`）**。Consensus-breaking，激活时间硬编码。不升则 DeBank follow 副本在 T7 激活点起 reject / 产生 invalid blocks、掉出同步、彻底停止采集。
- v1.10.1 **supersede v1.10.0**（后者因 workspace-version 检查失败未带 assets），同属 T7 release line。

### v1.10.1 主要更新内容（过只读 follow 副本筛后）

落在 DeBank 同步/采集路径上的真实收益（非 inert）：

1. **同步存续（硬分叉，核心）**——T7 共识规则变更。不升则副本在激活点掉出同步、停止数据产出。官方对 RPC Nodes 明列 High。

不构成 DeBank 收益的 inert 项（撑大 delta 但对只读副本无影响）：macOS libusb 安装器修复 #6274（容器只 build Linux 二进制，N/A）、validator failover、payload-builder gas-limit、bench-e2e 工具。

> 必要性与"是否触碰敏感路径"正交：T7 重写了 base fee / gas-refund / storage-credit 语义，**involved=true**，须实测 debank-rpc 输出一致性（见 §4）；但必要性由官方 required + 强制硬分叉的硬事实决定，与 21 个 conflict / 189 文件 delta 规模无关。

## 3. 部署情况（backup writer 测试形态）

**生产形态**：tempo **尚未迁移通用节点管线**——生产单 `node` 容器，**无 background-tracer sidecar**，node 不向 Kafka/S3/etcd 投递、不选主。DeBank 自定义 RPC（`trace_debankBlock`/`eth_multiCall`/`pre_traceMany`）是 **pull 拉取**，非 node push。

**测试部署**：单 `tempo node` 容器，dev box（x86_64 → 必须 amd64 镜像），从生产 seed 快照（60 GiB，约 4 天龄）建卷恢复，`--chain=mainnet`（PRESTO，chainId 4217 / `0x1079`）+ `--follow=auto`（`wss://rpc.presto.tempo.xyz`）跟随官方 WS 同步。

**is_backup：N/A——本家族（reth-Rust）无此机制**。`rg` 全库 `is_backup` / `VMTRACE_JSONCONFIG` 代码零出现（仅历史笔记）。render_note 里"VMTRACE_JSONCONFIG 注入 is_backup=true / config.toml 挂 /etc/config"是 geth 系通用模板提示，对 reth-Rust 不适用（无 VMTRACE、命令无 `--config`，reth 自动读 datadir 内 `reth.toml`），已忽略未注入。**backup ≠ 关投递**：本家族无可关的投递管线，故反过来——投递目标（自定义 RPC 产出）必须真实跑才能验 merge 没破坏它，`--http.api=all --ws.api=all` 全开。隔离改由结构性手段保证：

1. RPC/WS 仅 publish 到 `127.0.0.1`、不公开、不挂任何生产 RPC 端点组；
2. 无下游投递管线可污染（自定义 RPC 是 pull 拉取）；
3. 首启前清 p2p 身份（`<datadir>/discovery-secret[.bak]`、`known-peers.json`），让 peerid 重生，避免撞生产 writer。

无 S3/AWS 凭证需求（node 不访问 S3）。

> **升级注意点（follow 行为）**：v1.10.1 起 `--follow` 节点执行块前会验证 finalization certificates。追踪官方默认 RPC（本次 `--follow=auto` → 官方 WS）时无变化；若副本改 follow 本地 writer/validator，则该 validator 须用 `--ws` 暴露 websocket。
> **家族回写**：若日后 tempo 迁入 background-tracer sidecar（开始 push Kafka/S3 + etcd 选主），须重新评估其 backup 注入机制。

## 5. 其他问题 / 后续跟进

1. **T7 激活后下游跟进（mainnet 2026-07-09，非本 merge blocker）**：
   - **TIP-1067 Dynamic Base Fee**：`baseFeePerGas` 变 per-block 动态值（floor `600e6` / cap `12e9`）。下游若曾假设静态 base fee，须改读 `DebankBlock.base_fee_per_gas` per-block 字段（采集已正确填充，无需节点侧改动）。
   - **TIP-1060 Storage Credits**：state_diff / storage_contracts 新增 `STORAGE_CREDITS_ADDRESS` 持久存储地址，承载 per-account 存储信用余额。下游需识别该新增"合约"地址的存储变更，避免误判异常或漏读。
   - **TIP-1064 StablecoinDEX 订单存储信用**：新增相关 event（如 `OrderFlipped` 等），以普通 DebankEvent log 出现在 events，下游事件解码侧可能需识别新 selector。
   - **gas 会计语义变化**：storage credits 替代清零退款 + 移除 EIP-3529 退款上限 + 创建成本拆分；tx `gas_used`（来自 canonical receipt）与 trace gas 反映新成本，`pre_traceMany` 的 gasLimit×4 估算会看到 T7 gas 值——下游 gas 启发式需预期数值偏移。
2. **debank-rpc 回放路径 `.unwrap()` / 索引 panic 硬化（pre-existing，非本次引入）**：`trace_block.rs:144/324` 等处假设 `receipts.len()==txs.len()`，被 JSON-RPC per-request 任务隔离（只失败单个 trace 请求、不崩 sync/consensus）。v1.10.1 未改 receipt/tx 产出路径故不被 newly-trigger，但 T7 新 tx/费用类型（storage credits、AA-2D）逼近——建议 T7 激活前对这几处加显式边界检查。
3. **T7 行为复测**：本次覆盖 pre-T7 区间，T7 行为（2026-07-09 mainnet）未验证；建议激活后复跑 hash + trace_debankBlock parity。
4. **官方 RPC 交叉校验缺位**：官方 `rpc.tempo.xyz` 返回 403，本次以生产 archive 副本 parity 替代。后续若官方 RPC 可达，可补一次官方交叉校验。
